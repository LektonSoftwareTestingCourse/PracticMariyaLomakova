# Чек-листы периферийных сервисов СМП

Authorization и Card-Management не дублируются здесь: их проверки находятся в `test-design.md`.

## 1. Дымовое тестирование

### Gateway

- [ ] Доступность health-check Gateway и статусов обязательных downstream-сервисов
- [ ] Доступность основного endpoint приёма транзакций
- [ ] Доступность проксирования Cards, Search, Dashboard и обоих симуляторов
- [ ] Отклонение запроса с нарушением обязательной валидации
- [ ] Доступность Swagger UI

### Switch

- [ ] Доступность health-check Switch и Authorization
- [ ] Доступность внутреннего endpoint маршрутизации
- [ ] Маршрутизация транзакции с известным BIN
- [ ] Формирование контролируемого отказа для неизвестного BIN

### Terminal Simulator

- [ ] Доступность health-check Terminal Simulator
- [ ] Получение пула тестовых карт из Card-Management
- [ ] Завершение короткой симуляции `normal` через Gateway
- [ ] Согласованность счётчиков submitted, approved и declined

### Merchant Simulator

- [ ] Доступность health-check Merchant Simulator
- [ ] Завершение короткой симуляции обязательного сценария через Gateway
- [ ] Выбор MCC из конфигурации выбранного сценария
- [ ] Приоритет явно переданного списка MCC над списком сценария

### Transaction Logger

- [ ] Доступность health-check Transaction Logger
- [ ] Приём транзакции из очереди `transaction-log`
- [ ] Доступность поиска транзакций
- [ ] Доступность статистики и списка последних транзакций
- [ ] Установка WebSocket-соединения для потока транзакций

### Bin Lookup

- [ ] Доступность actuator health-check
- [ ] Получение данных эмитента для известного BIN
- [ ] Контролируемая обработка неизвестного BIN

### Notification Service

- [ ] Доступность actuator health-check
- [ ] Потребление карточного события из очереди `card-notifications`
- [ ] Доступность списка сохранённых уведомлений с пагинацией

### Web Dashboard

- [ ] Загрузка приложения без ошибки
- [ ] Отображение основных статистических виджетов
- [ ] Отображение последних транзакций
- [ ] Установка WebSocket-соединения с Transaction Logger
- [ ] Открытие деталей выбранной транзакции

### Инфраструктура

- [ ] Доступность PostgreSQL для сервисов, использующих хранение данных
- [ ] Доступность RabbitMQ и Management UI
- [ ] Наличие exchange и очередей для транзакций и карточных событий
- [ ] Отсутствие сообщений в DLQ после штатного smoke-прогона

## 2. Критический путь

### Gateway

- [ ] Валидация обязательных полей транзакции до вызова Switch
- [ ] Сквозное проксирование валидной транзакции в Switch
- [ ] Возврат ответа Switch без изменения бизнес-результата
- [ ] Обработка недоступности downstream-сервиса
- [ ] Срабатывание ограничения частоты запросов к транзакционному endpoint
- [ ] Передача `X-Request-Id` для трассировки запроса

### Switch

- [ ] Извлечение первых шести цифр PAN и выбор issuerId для известного BIN
- [ ] Отказ маршрутизации для неизвестного BIN
- [ ] Передача обогащённого запроса в Authorization
- [ ] Публикация полного результата APPROVED в `smp.transactions`
- [ ] Публикация результата DECLINED в `smp.transactions`
- [ ] Получение Publisher Confirm для принятого сообщения
- [ ] Reversal резервирования и системный отказ при отсутствии подтверждения APPROVED-транзакции

### Terminal Simulator

- [ ] Формирование транзакций сценария `normal` по картам из Card-Management
- [ ] Уникальность STAN в рамках запуска симуляции
- [ ] Отправка всех сформированных транзакций только через Gateway
- [ ] Разделение результатов запуска на approved и declined
- [ ] Формирование предусмотренных ТЗ decline-сценариев в сценарии `declines_test`

### Merchant Simulator

- [ ] Выбор мерчанта и MCC согласно сценарию
- [ ] Формирование суммы в диапазоне выбранного сценария
- [ ] Расчёт комиссии по категории MCC
- [ ] Отправка сформированной транзакции через Gateway
- [ ] Обработка сценариев grocery, electronics, restaurant и travel

### Transaction Logger

- [ ] Потребление сообщения, опубликованного Switch
- [ ] Сохранение полей исходного запроса, issuerId и результата авторизации
- [ ] Сохранение исходного MTI транзакции
- [ ] Поиск по предусмотренным фильтрам и пагинации
- [ ] Расчёт статистики по APPROVED и DECLINED
- [ ] Выдача последних транзакций в требуемом порядке
- [ ] Отправка новой транзакции подключённым WebSocket-клиентам

### Bin Lookup

- [ ] Обогащение Authorization данными эмитента для известного BIN
- [ ] Fallback на issuerId Switch при недоступности Bin Lookup
- [ ] Соблюдение контролируемого поведения при задержке и ошибке внешнего API

### Notification Service

- [ ] Публикация Card-Management события через outbox
- [ ] Маршрутизация события по ключу `card.*` в очередь уведомлений
- [ ] Сохранение типа события, routing key и payload уведомления
- [ ] Повторная обработка и переход в DLQ после исчерпания retry

### Web Dashboard

- [ ] Получение начальной статистики из Logger
- [ ] Получение списка последних транзакций
- [ ] Добавление новой транзакции в таблицу по WebSocket
- [ ] Обновление клиентской статистики после WebSocket-сообщения
- [ ] Отображение полных деталей APPROVED и DECLINED транзакций
- [ ] Автоматическое переподключение WebSocket после разрыва соединения

### Инфраструктура

- [ ] Целостность данных карты, счётчиков лимитов, транзакций и уведомлений в принадлежащих сервисам таблицах
- [ ] Отсутствие прямого чтения сервисами таблиц других сервисов
- [ ] Доставка транзакций через `smp.transactions` → `transaction-log`
- [ ] Доставка карточных событий через `smp.card-events` → `card-notifications`
- [ ] Доступность диагностических данных DLQ через RabbitMQ Management UI
